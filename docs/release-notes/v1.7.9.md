# v1.7.9 更新

## 紧急修复:v1.7.8 在 DSH Desktop 无法启动

**现象**:v1.7.8 在 DSH Desktop 上加载即报
`failed to import loader entry …(dsh-cost-meter): Cannot access 'Ge' before initialization`。

**根因**(不是 v1.7.8 新功能的错):v1.7.6 给 `custom-balance.js` 加
`store.js` 导入(共享密钥头判定函数)时,与既有的
`store → plan-billing → coding-plans → custom-balance` 边构成了 ESM 环。
环上 `plan-billing` 的顶层常量 `PLAN_PROVIDER_IDS = [...CODING_PLAN_PROVIDER_IDS, 'go']`
在模块初始化时立即读取邻居导出——原生 ESM 的固定执行序掩盖了问题,但
Desktop 的模块加载顺序不同,环被重排后顶层常量处于「暂时性死区」(TDZ)。
v1.7.8 新增的 gateway 模块恰好改变了加载图,把环翻转到了崩溃序;
CLI(`dsh web`)两种顺序都能跑,因此此前的实机冒烟没有暴露。独立首导入
`coding-plans` / `plan-billing` 在 1.7.7 与 1.7.8 同样必崩(已复现)。

**修复**:把 `looksLikeSecretHeaderValue` 迁到 **net.js**(插件里唯一零本地
依赖的底层模块,所有模块都已依赖它),custom-balance 改从 net.js 导入,
store.js 保留 re-export 兼容。导入图自此**无环**——任何加载顺序都不再
可能触发 TDZ。

新增回归测试:导入图静态无环断言 + 六个环敏感模块各自独立子进程首导入
(v1.7.8 必崩的用例)+ re-export 绑定一致性。

## CLIProxyAPI 网关额度功能已恢复

v1.7.8 的网关额度层(六家 Provider + WorkBuddy credits)在破环修复之上
重新合入,功能与 v1.7.8 发布说明完全一致——详见
[v1.7.8 更新](v1.7.8.md)。
