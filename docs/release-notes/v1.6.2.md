# v1.6.2 更新

## 修复(计费逻辑专项审计)

本版本是对全部计费链路(价格表 → 用量采集 → 账本存储 → 额度面板)的一次专项审计落地:10 项逻辑缺陷修复 + 7 项加固,重点是三类用户可直接感知的金额错误。

### 金额错误

- **客户端回退计价金额放大汇率倍**:设置页状态解析白名单丢失 `prices.currency`——官方价格币种为 CNY 时,会话徽章/明细的回退估算不除汇率、展示时又乘回汇率,金额放大 ~7.2 倍。
- **hunyuan-a13b 按 CNY 原值入账**:目录价 ¥0.5/¥2 此前直接按美元计费(~7 倍高估),已按默认汇率折算为 USD。
- **清空价格档 = 静默免费**:价格输入框全选删除后空串被提交成显式 0 价并持久化,该档位之后所有调用按 0 计费。现在 offPeak/peak 清空恢复「无档按基础价计」,基础价/汇率忽略误清。
- **模型名跨版本误配(issue #18 残留)**:`glm-5.3` 会经宽泛包含/前缀路径匹配到 `glm-5` 旧价(实测低计 ~29%),`gpt-5.9` 匹配到 `gpt-5-nano`;三个匹配阶段全部补齐数字分叉守卫。

### 漏计与覆盖

- **usage:null 击穿判空**:宿主异常收尾路径发出的空 usage 块会打断成本投影,或覆盖已捕获的有效用量快照导致整次调用漏计。
- **Anthropic 子配额覆盖主周窗**:`seven_day_sonnet`(如 3%)顶替整体周窗(`seven_day`,如 12%),采样列与满窗估算随之失真;子配额窗口已丢弃。
- **backfill 全覆盖判定漏 reasoning**:历史重算可能以不含推理成本的回放值无痕覆盖当日总额。

### 额度与面板

- **MiniMax 国际域 Key 恒报凭据无效**:双域端点(minimaxi.com/minimax.io)401 现在继续换域重试(与 Z.ai 同待遇)。
- **Kimi 滚动窗口估算失真**:`'1w'/'2d'/'30m'` 命名此前落入 48 小时兜底基线,满窗估算单位错配;现按时间量级归入最近标准周期。
- **第三方模型「取消挂载」永不生效**:配置合并会把已删除的模型复活;已改为替换语义。
- **自定义余额提取失败伪装成 $0**:null/空串不再被强转成 0 冒充成功读数(fail-loud)。
- **官方余额符号错位**:¥ 计价余额在 USD 显示档渲染成 "$53";符号现跟随记账币种。
- 其余:apiCost>cost 倒挂封顶、跨厂商兑底峰谷口径对齐、中文峰窗口紧凑排版兼容、去重键与回放对齐、超时不吞取消信号等。

## 升级

已安装用户在任意终端重跑一行即可(重跑即为更新):

```powershell
irm https://raw.githubusercontent.com/Han-1413141/dsh-cost-meter/v1.6.2/install.ps1 | iex
```

升级后**重启 dsh web** 使插件服务端代码生效,浏览器端刷新页面即可。
