# v1.6.7 更新

## 修复(计费口径专项)

本版本修复两个计费口径问题:峰谷生效时刻被价格同步重置导致的峰时历史半价重算,与币种切换不重算历史导致的新旧口径并存。

### 峰谷生效时刻被价格同步重置为「现在」(高危)

- **现象**:每次「从官方文档同步价格」之后,历史重算(会话徽章回放 / 按模型回填)会把同步时刻之前的**峰时段事件全部按谷价(半价)重算**——历史每日/会话费用向下漂移,峰时占比越高漂移越大。
- **根因**:官方价格页已不再标注「生效时间」字段,解析结果恒为空,同步的兜底分支把峰谷生效时刻写成了同步时刻;此后任何按时刻判档的重算都把更早的事件判为「峰谷尚未生效」而回落基础档(= 谷价)。
- **修复**:官方页无生效时间时不再改写该键;存量账本升级时自动把被污染的生效时刻钳制回 2026-08-16 16:00 UTC 历史分界(幂等迁移 `peak-effective-at-clamp-v1`)——该分界对全部历史判档均正确。

### 币种切换不重算历史 → 新旧口径并存

- **现象**:把「价格币种」从 USD 切到 CNY 并同步后,会话徽章变成 CNY 口径,而今日卡片 / 历史明细 / 余额条仍是 USD 口径——插件自身两个表面对同一天相差约 5%,与官方账单对比时表现为「误差更大」。
- **根因**:切换币种只替换价格表,存储账本完全没动;会话徽章(投影按当前表重算)与存储账本各自为政。
- **修复**:**切换币种即全量换基准**——后台回放会话日志,按新价表 + 修正后的生效时刻逐事件重定价,回放覆盖完整的日子整体替换,日志已清理的会话保持原口径;重算完成后提示重算天数与会话数。升级到本版时,此前切换过币种而新旧口径并存的存量账本自动重算一次(迁移 `currency-basis-recompute-v1`)。设置页「价格币种」说明同步更新为新语义。

### 已知近似(文档化)

- 客户端回退计价(会话徽章在账本数据不可用时的估算路径)按「当前时刻」的价格档位给该会话全部调用定价:跨峰谷时段的会话在峰时会高估其谷时部分,精确金额以账本为准(账本按每次调用的发起时刻逐笔计价)。README「已知限制」已补充说明。

## 验证

- verify.mjs 新增四组回归:同步不改生效时刻的源哨兵、半价缺陷金额级回归(污染时刻 vs 分界时刻恰为两倍)、clamp 迁移幂等、USD 口径账本切 CNY 重算后 = CNY 口径(含峰时事件 2 倍档)端到端断言。
- 真实账本影子验证(副本,不落盘):今日总额 ¥5.83(USD 口径)→ ¥5.74(CNY 口径),与官方 ¥5.64 的偏差从 ~3.4% 收窄至 ~1.7%;残差来自日志覆盖不全而保持原口径的会话,符合设计。

## 升级

已安装用户在任意终端重跑一行即可(重跑即为更新):

```powershell
irm https://raw.githubusercontent.com/Han-1413141/dsh-cost-meter/v1.6.7/install.ps1 | iex
```

升级后**重启 dsh web** 使插件服务端代码生效(生效时刻钳制与存量账本重算在启动时自动执行),浏览器端刷新页面即可。
