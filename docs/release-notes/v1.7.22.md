## v1.7.22 更新

### 会话日志与历史恢复

- **#132 / #133 / PR #135**：停止向宿主会话日志追加原生搜索私有事件，解决搜索后重启时整份会话被拒绝读取的问题。保留 PR 的止损目的与作者提交，移除不能证明持久化契约的函数源码探测。
- **原生搜索明细**：真实 usage 继续写入账本，并独立保存于账本旁的逐会话文件；历史导入与币种重算按请求 UUID 合并新明细和旧日志，重复搜索分别计数，重叠记录只计一次。不保存查询、响应正文或凭据。
- **旧会话修复工具**：新增 `dsh-cost-meter-repair-sessions`，默认只读检查；显式 `--write` 时取得宿主内核会话锁，保留原样备份后，只给本插件合法事件补 `ignorable: true`。保留未改动压缩帧；占用、截断、异常或超出预算的日志拒绝写入。详见 [恢复说明](https://github.com/Han-1413141/dsh-cost-meter/blob/v1.7.22/docs/session-history-recovery.md)。
- **#134 版本化日志**：识别 `session.vN.jsonl[.zstd]`，每个会话按数字选择最高代际，同代际优先压缩格式，排除备份、临时文件及非规范名称。历史回填、安装前导入、币种重算和 fork 种子清洗均覆盖新版文件名。
- 已运行过首次自动导入的用户，可在「设置 → 费用 → 用量 → 导入安装前历史」重跑。插件不自动重写宿主日志，也不重新导入用户主动清空的数据。

- 搜索独立文件落盘、会话金额、坏行恢复、UUID 去重、跨峰谷与双币种重算；版本化日志四条历史路径与重复导入。

## 升级与恢复

更新到 **v1.7.22** 并重启 DSH，阻止新的不兼容会话事件；新搜索仍按真实用量计费。

已出现“unknown event type … not marked ignorable”的会话不会因更新而自动改写。先退出全部 DSH，再执行以下命令（Node 22.15+ 或 Node 24）：

```sh
npx --yes --package=dsh-cost-meter@1.7.22 --package=@deepseek-ai/dsh@0.1.5-rc.2 dsh-cost-meter-repair-sessions --write
```

去掉 `--write` 为只读检查。每份修改的日志都有原样备份，工具拒绝抢写正在使用的会话。自定义数据目录需添加 `--sessions-root "/完整路径/sessions"`。完整步骤与限制见 [恢复说明](https://github.com/Han-1413141/dsh-cost-meter/blob/v1.7.22/docs/session-history-recovery.md)。

历史曾导入为空的用户，到「设置 → 费用 → 用量 → 导入安装前历史」重跑一次。已有会话条目不会重复叠加。

PowerShell 安装链：

```powershell
irm https://raw.githubusercontent.com/Han-1413141/dsh-cost-meter/v1.7.22/install.ps1 | iex
```
