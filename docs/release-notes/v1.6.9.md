# v1.6.9 更新

## 修复(计费审计:客户端/服务端口径漂移)

本版本源于一次全仓计费审计(完整报告见
[docs/code-audit-2026-08-28.md](code-audit-2026-08-28.md))。核心计费链路复核无误,
修复审计确认的三处客户端与账本口径不一致。

### 官方余额条「当日已用」漏计官方路由键

- **现象**:侧边栏官方余额进度条的「当日已用」段在纯官方路由的账本上恒为 0 或明显偏低,
  与「余额差对账」给出的官方渠道费用对不上。
- **根因**:官方路由实际落账键形如 `deepseek-official:模型`,而界面侧只认 `deepseek` 前缀。
- **修复**:双前缀同计,并剥离 `llm-` 包装路由前缀,与账本侧完全同口径。

### 会话徽章回退估算丢失峰谷档(峰时低估约一半)

- **现象**:会话内同时有订阅(Plan)渠道与按量渠道时,徽章把金额拆成「API + Plan 等值」
  展示;拆分用的重算路径把峰/谷价格子档丢掉了——峰时调用被按谷价(半价)重估。
- **修复**:峰/谷/历史价格子档随主档保留;峰时、谷时、周末、峰谷时代分界前四个相位的
  档位与金额恢复与账本逐位一致(新增行为级测试防再次漂移)。

### 小数位设为 0 仍显示两位(纯显示)

- 设置里把「小数位数」设为 0 后,金额仍显示两位小数;现与账本侧同规则保留 0。

### CI:回归门禁首跑红(时区炸弹)

- v1.6.8 把回归套件接入 CI 后,ubuntu/windows 两腿在「SCNet 计费周期」同一条断言失败:
  断言把自然月起点写死为 `2026-08-01`,而 CI 时区(UTC)下同一时刻的本地日历月是 7 月——
  实现按运行时本地日历计算没有错,是断言写死了时区。现期望值由测试进程本地日历推导,
  任意时区自洽(已用 UTC / UTC-8 / UTC+14 / UTC+8 四种时区全量验证)。

## 升级说明

- 无配置变更、无账本迁移;升级重启即生效。
- 已有账本金额不受影响——本版修复的是**界面侧**的口径漂移与 CI 门禁,账本存储口径自
  v1.6.7 起即为单一基准。
