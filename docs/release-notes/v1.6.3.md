# v1.6.3 更新

## 修复

本版本修复两个用户报告的问题:modlens 视觉包装层导致的重复计费(issue #70)与火山方舟 Coding Plan 额度解析失败(issue #71)。

### modlens 重复计费(issue #70,报告 @lucas-wang-1)

- **现象**:开启 modlens 插件后,账本 token 与费用整体翻倍——同一次调用在上游与 `modlens-<upstream>`(官方路由为 `deepseek-modlens`)包装层两个 provider 键下各入账一次。
- **根因**:modlens 为承载纯文本模型的 provider 路由自动注册视觉包装模型,并在监听器体内再发起一次上游 `llm.stream` 转发同一份 usage;该内层分发逃逸了计费流的嵌套调用深度标记,实时钩子、会话投影与历史回放全部照单全收。
- **修复**:三个计费入口(实时 llm/stream 钩子、costUsage 投影、backfill 历史回放)统一跳过包装层 provider 事件,只记上游真实流。
- **历史数据**:启动时一次性清洗存量账本(幂等迁移 `modlens-wrapper-dedup-v1`)——镜像对扣除包装层份;与旧版指纹合并的混存残留按四形态精确修正(改挂上游键 / 扣除镜像份);无法安全判定的条目保守不动。升级后历史每日/会话费用将自动恢复真实值。

### 火山方舟 Coding Plan 额度解析失败(issue #71,报告 @suyukun)

- **现象**:Coding Plan 用户额度面板始终无读数或全 0。
- **根因**:管控面 Action 白名单缺 `GetCodingPlanUsage`——这才是 CodingPlan 官方用量接口(无参即返回 `Result.QuotaUsage[]` 的 session/weekly/monthly 三窗百分比);而此前位列首位的 `GetAFPUsage` 实为 AgentPlan 接口。
- **修复**:`GetCodingPlanUsage` 置于白名单首位,解析器补 `QuotaUsage` 数组与 `Level` 窗名字段;原三个 Action 保留作兜底变体。升级后无需重新配置,AK/SK 签名与调用方式不变。

## 升级

已安装用户在任意终端重跑一行即可(重跑即为更新):

```powershell
irm https://raw.githubusercontent.com/Han-1413141/dsh-cost-meter/v1.6.3/install.ps1 | iex
```

升级后**重启 dsh web** 使插件服务端代码生效(历史账本清洗在启动时自动执行),浏览器端刷新页面即可。
