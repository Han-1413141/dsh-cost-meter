# v1.7.8 更新

## 新功能:CLIProxyAPI 网关额度适配层(issue #87 / PR #90)

经 [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI)(CPA)统一承载多
OAuth 账号的用户,现在可以在 dsh 里直接看到网关侧各账号的额度窗口——与既有
直连 Coding Plan 并列的独立「网关额度」层,由 CDeZT 贡献实现。

### 支持的 Provider

| Provider | 窗口 |
|---|---|
| Antigravity | 5h + Weekly(配额摘要,多桶解析) |
| Claude | 5h / 7d / 模型级周窗 |
| Codex | 主/副用量窗 + code review 限额 |
| Kimi | 5h + 周限额窗 |
| xAI (Grok) | 周 credits + 月 billing(只读双端点) |
| WorkBuddy | 账户 credits / 剩余 / 套餐周期 |

每账号独立显示(百分比语义统一为**已用** 0–100,多账号不合并平均),窗口带
reset 时间;未知 Provider 明确标注 unsupported,不猜测数字。

### 配置与凭据

- 设置 → 额度 →「网关额度」:添加 CPA source(baseURL + 白名单主机 +
  Provider 范围 + 刷新间隔),上限 4 个;
- **Management key 走 DSH 凭据库**(write-only 输入框,不落盘、不回显、
  不经 ledger.json),与模型页/自定义余额同一套凭据机制;
- baseURL 默认只放行 loopback(localhost / 127.x / ::1);远程 CPA 实例必须
  显式把主机加进 source 的 allowedHosts(精确 host[:port]),非 loopback 的
  HTTP 还需显式开启 allowInsecureHttp。

### 安全边界(设计约束)

- 插件自身只请求 CPA 管理端点(auth-files / api-call / WorkBuddy credits);
  上游 Provider URL 仅作为 api-call body 参数由 **CPA 转发**——`$TOKEN$` 在
  CPA 侧替换成真实 token,token 永不进入插件进程;
- auth-files 只取脱敏元数据(auth_index / provider / email / plan 等),
  token / cookie / id_token 等敏感字段在解析入口即丢弃;
- **副作用端点硬闸**:会烧积分(Codex 消费端点)或消耗 token(对话补全)的
  请求一律拒发——额度表绝不允许产生计费副作用;
- 响应体 256KB 上限、redirect 拒绝、错误消息脱敏(URL 替换为 [endpoint]);
- 失败时保留 last-known-good 快照(stale 状态),逐账号错误不拖垮整个 source。
