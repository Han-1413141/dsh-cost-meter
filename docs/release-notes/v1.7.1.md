# v1.7.1 更新

## 紧急修复:v1.7.0 导致 dsh 无法启动

**现象**:安装/升级到 v1.7.0 后 `dsh web` 启动即失败:

```
Error: dsh: plugin tree failed to load: ... typert-loader:
dsh-cost-meter invocation "dsh-cost-meter#costMeter/refreshCustomBalance"
parameter codec must use a strict codec
```

**根因**:v1.7.0 给「自定义余额刷新」接口新增的 `index` 参数(多配置支持),其
codec 声明**裸传了 zod schema**,而 typert 契约要求 strict codec 对象
(`{ mode: 'strict', typeSymbol, schema }`)——typert-loader 在注册期即拒绝,
整个插件树加载失败,宿主无法启动。测试此前只覆盖服务端逻辑、未覆盖 manifest
注册层,因此逃过了发布检查。

**修复**:

- 两侧 manifest 的 `index` 参数改为标准 strict codec 对象;
- 补 `acceptsUndefined` 标志——旧客户端的无参调用(等价「刷新全部」)继续可用;
- verify.mjs 新增**宿主级 manifest 校验**回归:直接用 dsh 官方 typert-loader 的
  校验函数对本插件清单做全量真实校验,此类错误今后在测试期即暴露。

另:升级过程中若还看到 `dsh-typert-registry/client.js failed to load`,那是
dsh 宿主自身组件的浏览器端加载问题(与本插件无关);本机实测 v1.7.1 下
`dsh web` 可正常启动。若它单独出现,重启 dsh 或清理浏览器缓存即可,仍复现请
向 dsh 官方反馈。

## 升级说明

```powershell
irm https://raw.githubusercontent.com/Han-1413141/dsh-cost-meter/v1.7.1/install.ps1 | iex
```

更新后重启 `dsh web` 即可。从 v1.6.x 直接升级的用户不受影响(v1.7.0 存在的
时间很短,多配置功能在 v1.7.1 中完整可用)。
