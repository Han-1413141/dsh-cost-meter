# v1.7.7 更新

## P0 修复:大日志回填 OOM 崩溃(issue #88)

用户实测:环境里存在 168MB(压缩后)的 `session.jsonl.zstd` 时,安装插件并重启
后约 3 秒(agent 界面先整体卡死)主进程崩溃(STATUS_BREAKPOINT / V8 堆耗尽)。
崩溃点正是启动回填定时器读取大会话日志的路径。此前 v1.5.x 的「逐帧解压」
缓解只压住了**解压拼接**的峰值,仍剩两个洞:

1. **事件循环卡死**:整个文件同步解压(10 万+ 帧要数分钟),期间宿主 UI 无响应;
2. **堆耗尽**:`records` 数组物化解压后全部事件对象,巨长打包行
   (`text-chunks` 等)还逐行付出 JSON.parse 的瞬时峰值。

本版把回填链路(回填 / 安装前导入 / 币种重算 / fork 清洗四条路径)全部切到
**流式迭代器** `iterateSessionRecords`:

- 分块读文件(8MB/块) + 增量扫描 zstd 帧边界,完整帧**立即解压、逐行产出、
  释放引用**——任一时刻只持有单帧解压结果,不再物化全文;
- 每 64 帧 / 4096 条事件 `setImmediate` 让出一次事件循环,回填期间宿主 UI
  保持响应;
- **打包行探针**:超 4096 字节的行先看头部 512 字符,命中打包行模式直接跳过,
  不再为巨长行付出 JSON.parse 峰值(短行/未命中仍走正常解析+过滤,行为不变);
- **解压预算**:单文件累计解压超 4GB 抛错(防解压炸弹),按「单文件损坏」
  跳过该文件,绝不把主进程拖崩;结构损坏区域与旧版全量扫描同语义
  (在首个非法结构处停止,此前记录完整保留)。

## 修复:对账「官方余额当日变动」虚高(issue #89)

赠送余额(granted)有到期日。当它在某天恰好归零时,官方总余额(total)的当日
减量里混入了**整块赠送失效**的金额——那不是消费,与本地账本今日费用必然对
不上,「余额变动」一侧虚高数倍,触发误导性对账警告。

现该日(基准时有赠送余额、当前已归零)按**重置基准**处理,不对账、不告警
(与既有的「充值/授予增加 → 重置基准」守卫对称);此后从零余额起继续对账。
granted 维持剩余的普通场景口径不变。
