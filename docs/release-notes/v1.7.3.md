# v1.7.3 更新

## 改进:中转链路「缓存未上报」的显式标注(issue #65 讨论)

**背景**:经中转/代理(如 cherrystudio)调用 DeepSeek 时,可能出现:

- 中转重新组包转发,**剥掉** usage 里的缓存扩展字段
  (`prompt_cache_hit_tokens` / `prompt_tokens_details.cached_tokens`);
- 或中转请求的上下文与原会话字节级不一致,prefix cache **真实未命中**。

两种情况在插件端的表现相同:缓存命中率恒 0%,金额按全未命中价计(上界)——
此前显示「0.0%」无从区分「真零命中」与「数据缺失」,造成「金额比官方账单高、
缓存永远不命中」的观感(#65 报告者的实测症状)。

**本版改进**:设置 → 「按模型统计」面板对「累计 ≥3 次调用、非缓存输入
≥100k token 而缓存命中恒为 0」的模型(该形态下直连的 prefix cache 几乎必然
命中,恒零大概率是链路问题):

- 缓存命中率单元格显示 **「未上报?」** 而非误导性的 0.0%;
- 费用排行与命中率行均附 ⚠ 悬停说明:命中率无法统计、金额按全未命中价计
  (上界)、直连官方 API 可恢复准确缓存命中与更低金额;
- 真·零命中(单轮/短上下文/冷启动)不满足量级阈值,**不会被误标**。

**能力边界(如实说明)**:插件无法恢复被中转剥离的数据,也无法修复中转导致的
真实缓存未命中——请求由宿主与中转层组装,插件仅是计量方。本改进消除的是
误导性显示;要恢复准确的缓存命中,请让 dsh 直连官方 API Key
(baseURL = api.deepseek.com)。
