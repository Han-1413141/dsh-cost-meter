# v1.6.11 更新

## 修复:modlens 包装路由的调用不进账(issue #76)

**现象**(报告者 @paicat1,实测 v1.6.8):经「(modlens vision)」包装模型(`modlens-go-ds4f` /
DeepSeek-V4-Flash)发起的调用从不进账——会话日志里有 usage,但账本 sessions=0,
侧边栏「今日费用」恒 ¥0;只有绕开包装直连的调用被记录。

**根因**:`modlens-go-ds4f` 命中包装层判定(`modlens-` 前缀)。#70 时代的防重复计费修复
把包装层 provider 的 usage **一律丢弃**、只记「上游真实流」——但这类转售路由整条链都是
包装型 id,上游不产生独立的非包装流,于是唯一到达的 usage 也被丢弃,整单漏计。同一缺陷
也存在于会话费用徽章(投影)与历史回放。

**修复**:改为**指纹窗口去重**——包装层样本先改挂上游 id,再按「模型 + 五桶 token 逐位
指纹(10 秒窗)」与已计入样本互斥:

- #70 的「包装层 + 上游」转发对无论哪个先到,都只记一次(原语义保持);
- 包装层单链(转售路由)照常入账,不再整单漏计;
- 合法的两次同量普通调用互不去重,与旧行为一致。

账本入账钩子、会话投影、历史回放三个入口同语义,回归测试锁定双序一致性。
注:此前被丢弃的调用没有账本数据可恢复,只有此后的调用会入账。

## 修复:本地模型被按云端价误计(issue #76 附带)

本地网关模型(如 `lmstudio:qwen3.8-9b-heretic-uncensored-i1`)此前会经跨厂商兜底的
模糊匹配误套同家族云端价(实测按阿里 `qwen3.8-max` 单价,64 次多计 $3.29):

- **自动零消耗**:本地来源 provider(lmstudio / ollama / vLLM / SGLang / TabbyAPI /
  Jan / GPT4All / llama.cpp / LocalAI / koboldcpp / lmdeploy / oobabooga /
  text-generation-webui / llama-server)与模型 id 前缀(`lmstudio:` / `ollama:` /
  `vllm:` / `sglang:` / `gguf:` / `local:` 等)自动按未定价处理——token 照记、费用 0;
- **历史修正**:启动时一次性把账本中本地来源条目的误计金额归零(token 保留,日/会话
  合计同步扣回,幂等);
- **需要计费时**:价格映射下拉手动为其指定任意价格条目(显式覆盖优先)。

## 新增:已命中模型可改映射 + 本地模型零消耗开关

- 设置页「费用 → 价格 → 模型名匹配」的目标下拉新增**「本地模型（零消耗）」**:任意模型
  (含已自动命中的云端模型)都可标记为本地——token 照常统计、费用按 0 计,写入后
  **历史金额即时归零**;
- 新增**「本月已命中价格的模型」**区块:此前只能为「未命中」的模型手动指定条目,现在
  已自动命中的模型同样列出,行内选择目标即可改挂其它价格条目;
- 界面中英双语;取消本地标记后历史 0 值不自动回溯(如需重算历史可用币种切换的全量重算)。

## 改进:今日费用实时刷新

此前侧边栏「今日费用」靠 60 秒轮询:计费本身在流结束的瞬间就已入账(2 秒写盘防抖只影响
持久化,不影响界面),但界面要等下一个轮询周期才更新——平均半分钟、最坏一分钟。而且
「本会话费用」徽章走宿主推送是实时的,反差更明显。本版:

- **流结束 ≈1 秒内更新**:客户端监听会话用量的实时推送(每次入账即触发),防抖 800ms
  后刷新快照;60 秒轮询保留作兜底;
- **刷新不再被网络查询卡住**:余额/额度类快照改为「有旧值立即返回、过期数据后台静默
  刷新」;首次加载仍等待真实数据;设置页各卡片的手动刷新行为不变。

## 升级说明

- 安装/更新:

  ```powershell
  irm https://raw.githubusercontent.com/Han-1413141/dsh-cost-meter/v1.6.11/install.ps1 | iex
  ```

- 更新后重启 `dsh web` 生效;启动时会自动执行本地模型误价清洗(仅一次,幂等);
- 使用 modlens 包装路由的用户无需任何配置,升级后新调用即正常入账;如需把该路由
  按特定价格计费,在「模型名匹配」里为其指定价格条目即可。
