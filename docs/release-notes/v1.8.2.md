# v1.8.2 — Fix statistics Remote registration

## English

Fixes #210: opening **Settings → Cost → Cost statistics** or **Conversation cost details** could fail with `typert: Remote package "dsh-cost-meter" is already registered`. This also affected v1.8.1.

The main client already registers its Remote contribution. The lazy statistics module now has a separate registration identity while keeping the same `costMeter` endpoints and type symbols. Both groups can coexist, unload and register again. Statistics still load on demand, and their API boundary validates inputs and results.

The old failure was reproduced with the actual browser registry and gateway from both DSH **0.1.7-rc.2** and **0.2.0-rc.2**. The fixed lifecycle passes on both: first/concurrent/repeated open, failed-load retry, both statistics RPCs and plugin unload/reload. CI now runs this test for both versions, including a negative control using the original conflicting identity. Full local regression also passed.

## 简体中文

修复 #210：打开**设置 → 费用 → 计费统计**或**本会话费用明细**时报 `typert: Remote package "dsh-cost-meter" is already registered`。v1.8.1 同样受影响。

主客户端已经注册了自己的 Remote contribution。统计模块现在使用独立的注册标识，继续使用原来的 `costMeter` 接口和类型，两部分可以共同加载、卸载并重新注册。统计界面仍按需加载，并在 API 边界校验参数和返回数据。

使用真实 DSH **0.1.7-rc.2** 和 **0.2.0-rc.2** 浏览器 registry/gateway 均复现了旧版错误；修复后通过首次、并发及重复打开、加载失败重试、两个统计接口和卸载重载测试。CI 新增这两个版本的检查，并保留原冲突标识作为失败对照。完整本地回归通过。

## Update / 更新

```sh
dsh plugin --profile web add dsh-cost-meter@1.8.2
```

Restart DSH and refresh the page after updating. Desktop users should use the application's own CLI and `desktop` Profile as described in the [installation guide](../install-troubleshooting.md#desktop-安装与更新).

更新后重启 DSH 并刷新网页。桌面端请按[安装说明](../install-troubleshooting.md#desktop-安装与更新)使用应用自带 CLI 和 `desktop` Profile。
