# v1.6.12 更新

## 修复:压缩摘要调用漏计(issue #77)

**现象**(报告者 Li Zhuojun):长会话触发上下文压缩(compaction)时,宿主会把旧上下文
发给模型做一次摘要调用——这是一次真实的 provider 计费。但它的用量记录在
`compaction/summary` 事件上(一个 log-only 事件,不是循环步),本插件的会话徽章与
历史回放此前只认 `assistant/chunk` / `assistant/message` 两种事件,摘要调用的 token
全部漏计。实测:3 次压缩共 48,895 token,单次 MiniMax-M3 摘要 44,444 token
(536 输入 / 2,436 输出 / 41,472 缓存读)被记 0。

**影响面核实**:

- 侧边栏「今日费用/账本」**不受影响**——摘要调用走 `ctx.llm.stream()`,实时计费钩子
  本就覆盖(经上游 summarizer 源码 `llmStreamCall` 标记核实);
- 会话费用徽章与历史回放(含按模型统计回填)此前漏计,本版修复。

**修复方式**:

- 投影折叠与历史回放计入 `compaction/summary` 的 `usage`(可选字段——供应商未上报
  时不产生缺口);
- 归因优先用**事件自带路由**(摘要调用可能不是当前会话路由的模型;新旧两代宿主字段
  形态 `data.message.source.{provider,model}` 与 `data.{provider,model}` 都兼容),
  缺省回落会话当前的 header 计费口径;
- 摘要样本使用独立去重键(不占 `(turn, step)`),与循环步的流式/最终样本替换互不干扰,
  也豁免包装层转发指纹窗口(摘要结果是单源日志事件,没有转发对);
- 投影状态版本 7 → 8:升级后宿主对历史会话重新折叠,此前的摘要用量自动补齐
  (v1.6.11 的包装层改挂计数也一并自愈)。

## 升级说明

- 安装/更新:

  ```powershell
  irm https://raw.githubusercontent.com/Han-1413141/dsh-cost-meter/v1.6.12/install.ps1 | iex
  ```

- 更新后重启 `dsh web` 生效;历史会话的摘要用量在投影重放后自动补齐,无需手动操作;
- 账本(侧边栏金额)无需修正——实时计费此前已覆盖摘要调用。
