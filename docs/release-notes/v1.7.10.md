# v1.7.10 更新

## 紧急修复:dsh 仍报 Cannot access 'Ge' before initialization(v1.7.9 之后)

**现象**:v1.7.9 修复了 DSH Desktop 宿主侧的模块循环导入,但 dsh 依然提示:

```
Failed to load plugins
failed to import loader entry …(dsh-cost-meter): Cannot access 'Ge' before initialization
```

这次崩的是**浏览器端 client bundle**:宿主 `__ModuleLoader__` 首次调用
client factory 时直接抛错,插件所有界面(dock / 侧边栏 / 设置页)都不加载。

**根因**(与 v1.7.8 是两处独立的雷,错误文案恰好相同):v1.7.8 的 gateway
提交在 `src/client.js` 里写下了自引用常量:

```js
const GATEWAY_PROVIDERS = GATEWAY_PROVIDERS   // 真值从未给出
```

esbuild 压缩后即 `const Ge=Ge`——factory 求值到这条语句必然触发 TDZ
ReferenceError。该行随 v1.7.9 的 gateway 重新合入继续在线上。
v1.7.9 的无环回归只覆盖宿主侧 `lib/*.js`(client.js 被显式排除),
浏览器端 bundle 门禁又只做语法编译、从不执行,双双漏过。

**修复**:补上与服务端 `lib/store.js` 的 `GATEWAY_PROVIDER_IDS` 完全一致的
六家字面量数组(antigravity / claude / codex / kimi / xai / workbuddy),
重建 `lib/client.js`(262074 bytes,仍在 262144 的 DSH STORE 单文件上限内)。

新增回归测试:浏览器端 bundle **执行**门禁——在 vm 里用良性 DOM 桩真正执行
bundle 顶层并全程求值 factory,任何初始化期引用错误(自引用 const /
顶层 use-before-init)当场失败。v1.7.9 形态在此门禁下必崩(已复现),
修复后全量测试绿。
