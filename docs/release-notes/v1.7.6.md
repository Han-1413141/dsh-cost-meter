# v1.7.6 更新

## 安全与体验:自定义余额凭据治理(issue #86)

### 1. 明文密钥不再落盘 / 下发

v1.6.8 的「密钥一律进 DSH 凭据库」治理只覆盖了 goQuota / codingPlans 的专属密钥
字段;自定义 Provider 余额请求头里的明文 key(`"Authorization": "Bearer sk-…"`、
`"X-Api-Key": "sk-…"`)会**原样写进 `ledger.json` 并随页面下发浏览器**。本版补齐:

- `stripSecrets` / `stripSecretPatch` 对 `customBalances[].request.headers` 按**值形态**
  判定脱敏——敏感头名(Authorization / api-key / token / secret / cookie 等)的非占位符
  值、典型密钥形状(Bearer / sk- / AIza / ghp_ / JWT / ≥32 位混合字母数字长串)一律置空;
- `{{VAR}}` 占位符与普通头(Content-Type / Accept 等)照常保留,不受影响;
- 落盘、下发、updateConfig 补丁三条路径走同一道闸门。

### 2. 存量明文自动迁移(不丢功能)

启动时把请求头里的遗留明文导入 DSH 凭据库,并把头值替换为
`{{CUSTOM_BALANCE_KEY_…}}` 占位符(名称由「条目 host + 头名」稳定哈希派生,跨重启
一致)——重启后余额查询照常工作。与既有密钥迁移同一套结局语义:凭据库已配置则
不覆盖;不可写则保留明文仅运行期使用(不落盘、不下发)并提示,**绝不静默丢密钥**。

### 3. 凭据外带防护覆盖明文 key

v1.6.8 的 allowedHosts 白名单只对 `{{VAR}}` 占位符生效,明文 key 完全绕过校验——
而明文恰恰是「导入他人配置」场景里最容易外带的形态。现判定扩展为
「占位符 **或** 疑似明文密钥」:发往白名单外主机的请求直接拒绝;未配置白名单时
放行并在日志警告一次。

### 4. UI 补齐(本版新增入口)

- **「凭据白名单主机」输入框**:条目展开配置里,逗号分隔(此前 allowedHosts 是
  官方字段但无任何 UI/文档入口,警告了却没处配);
- **「凭据输入」区**:请求头里每个 `{{VAR}}` 占位符一行 write-only 输入框,密钥
  直接存入 DSH 凭据库(不落盘、不回显、不经 `ledger.json`)——与模型页共用同一
  变量名即共用同一把密钥;写入后相关余额快照立即作废重查;
- **命名规则说明**:「请求头 (JSON)」上方标注 `<ROUTE>_API_KEY` 规则——
  `<ROUTE>` 为模型页 Provider ID 大写、非字母数字换下划线,如
  `openai`→`{{OPENAI_API_KEY}}`、`abc23-d`→`{{ABC23_D_API_KEY}}`。

### 5. 文档

中英 README 均补全 `allowedHosts`、`{{VAR}}` 占位符、命名规则、明文迁移与
白名单两种行为(名单内放行 / 名单外拒绝 / 未配置警告)的说明。

## 升级说明

```powershell
irm https://raw.githubusercontent.com/Han-1413141/dsh-cost-meter/v1.7.6/install.ps1 | iex
```

更新后重启 `dsh web` 生效;首次启动会自动迁移请求头里的存量明文密钥(控制台
有迁移日志)。历史余额数据与查询行为不受影响。
